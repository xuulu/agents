# AI Agent Project Kit

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

> **语言切换：** [English](README.md) | [简体中文](README.zh-CN.md)

你的 AI 编码助手，大概是这个星球上最热情、也最能拆家的"实习生"。它还没看懂需求就敢抡键盘，凭记忆凭空捏造 API，对项目里的依赖版本视若无物——为了改一行字，它能顺手把整个架构推倒重来。更离谱的是，它把每一次报错都当成人生的重大事件，郑重其事地写进"永久记忆"，仿佛那是它此生最珍贵的领悟。

这个套件，就是给这位"新同事"补上的入职第一课：先看懂，再动手；不许瞎猜，不许乱改；改完必须验证；值得记住的才往脑子里存。装上它，AI 还是那个 AI，但终于从"拆家小能手"变成了"靠谱队友"。

## 这是什么？

一套不绑定任何技术栈的 AI 编码代理项目规范，外加一套持久化项目记忆系统。

重点不是让 AI 多写代码，而是让 AI 在一个已经存在的代码库里老老实实干活——不瞎猜、不搞破坏、不把项目历史变成噪音。

工作流程：

理解需求
  ↓
调查项目
  ↓
确认依赖和版本
  ↓
理解状态与数据流
  ↓
确定最小修改
  ↓
编码
  ↓
验证
  ↓
只保存真正有价值的长期知识

不绑定任何技术栈，前端、后端、全栈、API、CLI、Web、Desktop、Mobile、Rust、Go、Python、Java、Node.js、React、Vue、Next.js、Monorepo 都能用。

⸻

## 为什么需要它？

AI Coding Agent 翻车，通常不是因为不会写代码，而是因为：

* 没理解需求就开始写
* 凭记忆猜 API
* 不检查依赖版本
* 不看已有实现
* 不理解全局状态
* 不检查调用方
* 为一个小需求大规模重构
* 报错后瞎试一气
* 为了让测试通过而隐藏问题
* 每次犯错都记一条"永久记忆"
* 项目跑几个月，记忆越来越乱

这个项目要回答的就一个问题：怎么让 AI 在同一个项目里，长期稳定、低噪音地干活。

⸻

## 什么时候适合使用？

1. **长期维护的项目**——项目已经跑起来，还会继续开发，AI 会反复参与：已上线的 Web 项目、长期维护的 API、SaaS、后端服务、前端项目、开源项目、个人长期项目。

2. **频繁使用 AI Coding Agent**——如果你常用 Claude Code、Cursor、Codex、Cline、Roo Code、Windsurf，或者任何支持 AGENTS.md 的工具。规则定义一次，不用每次聊天都重新交代。

3. **架构或状态复杂**——多服务、多数据源、全局状态、缓存、数据库、外部 API、权限系统、复杂生命周期。这种项目里，"先理解再修改"尤其要命。

4. **经常踩版本坑**——AI 记得一个更新的 API，项目跑的是旧版本，生成的代码直接崩。规则强制 AI 先用实际版本确认 API，再动手。

5. **有反复出现的项目知识**——源码里看不出来的限制："当前依赖不支持 API X，要用 Y"、"只有模块 A 拥有这个状态"、"这个 API 必须兼容旧客户端"。这些才值得进 .ai/。

⸻

## 什么时候不需要？

一次性小脚本、临时 Demo、几十行测试代码、一次性实验——直接用 AI 就行，没必要建整套记忆系统。

## 快速开始

先选语言目录（`en/` 或 `zh-CN/`），然后二选一。

**方式一：下载 ZIP**

在 GitHub 页面点击 **Code → Download ZIP**，解压后打开 `en/` 或 `zh-CN/` 目录，把 `AGENTS.md` 和 `.ai/` 整个复制到你的项目根目录。

**方式二：克隆仓库再复制**

```bash
git clone https://github.com/xuulu/agents.git
cd agents/zh-CN            # 或：cd agents/en
cp AGENTS.md /path/to/your-project/
cp -r .ai/ /path/to/your-project/
```

完成。`AGENTS.md` 是 Agent 读取的规则入口；`.ai/` 是 Agent 往后沉淀筛选项目记忆的地方。

## 第一次使用

别想着第一天就把 .ai/ 全填满。先从项目本身开始，让 AI 慢慢积累：

PROJECT.md
ARCHITECTURE.md
DECISIONS.md

TROUBLESHOOTING.md 可以等真正出现有长期价值的重复问题后再写。

一个好用的初始化指令：

请先阅读项目并初始化 .ai 项目记忆。
只记录已经确认、未来可能影响开发、且源码中不明显的信息。
不要猜测，不要记录临时问题。

## 架构修改

动数据库、全局状态、API、核心模块、服务边界、认证、缓存、外部服务之前，Agent 应该先读相关记忆：

PROJECT.md
ARCHITECTURE.md
DECISIONS.md

改完之后，只有在确实产生了新的长期知识时才更新记忆。

⸻

## Debug

查 Bug 先看 TROUBLESHOOTING.md。但别什么报错都往里面记。只有根因确认、方案验证过、以后很可能再犯、而且源码里看不出来的问题，才值得存。

⸻

## 推荐项目结构

装完之后，目标项目应该是这样：

```
your-project/
├── AGENTS.md
└── .ai/
    ├── PROJECT.md
    ├── ARCHITECTURE.md
    ├── DECISIONS.md
    └── TROUBLESHOOTING.md
```

Agent 实际读的入口是 `AGENTS.md`。别建 src/AGENTS.md、components/AGENTS.md、api/AGENTS.md——默认就一个根目录规则文件。

⸻

## AGENTS.md 是干什么的？

AGENTS.md 规定 AI 该怎么干活：理解需求、调查、不许猜、检查依赖版本、分析状态、尊重架构、控制范围、Git 卫生、Debug、安全、性能意识、测试验证、持久记忆、沟通。它应该保持相对稳定。

选适合你团队的目录：`en/` 是英文版，`zh-CN/` 是简体中文版。

⸻

## .ai/ 是干什么的？

.ai/ 存放项目长期知识。它不是聊天记录，不是 AI 日记，不是错误日志，也不是实现细节的垃圾桶，只装未来开发真正用得上东西。

* **PROJECT.md** —— 稳定事实：项目用途、技术栈、重要版本、运行环境、关键依赖、常用命令、部署、长期约束。
* **ARCHITECTURE.md** —— 源码里看不出的架构：模块边界、数据流、状态所有权、生命周期、外部服务、持久化、约束。别给每个文件都写一笔。
* **DECISIONS.md** —— 不该随便推翻的决策：为什么选这个架构、为什么用这个依赖、API/数据设计上的取舍。
* **TROUBLESHOOTING.md** —— 已确认的重复问题，按"症状 → 根因 → 已验证方案 → 适用条件"记。别存原始日志。

⸻

## 什么情况下应该写入记忆？

这是整套系统的核心。AI 不该给每次报错、每个纠正都建一条记忆。只有下面五条**同时满足**才存：

已确认
+
未来很可能再次使用
+
当前源码中不明显
+
没有已有记录
+
可以简洁表达

否则——别存。

### 不应该记录

今天 npm install 失败。
今天 TypeScript 报了个错。
用户让改一个按钮。
有次测试没过。
方案 A 不行，试了方案 B。

这些基本没有长期价值。

### 应该记录

当前使用的某依赖版本不支持 API X。
必须使用 API Y。

它值得存，是因为它确认过、和版本绑定、以后很可能再犯、而且普通代码里看不出来。

⸻

## 不要把 .ai/ 变成垃圾桶

别把每次报错、每次测试失败、每次 AI 尝试、聊天记录、临时环境问题、用户每句话、源码里明摆着的东西，一股脑全塞进 .ai/。

正确目标：100 次开发 → 只沉淀少量真正重要的知识。而不是：100 次开发 → 攒几千条 AI 日志。

⸻

## 为什么只保留一个 AGENTS.md？

默认刻意不用 src/AGENTS.md、components/AGENTS.md、api/AGENTS.md。一个项目 = 一个根目录 AGENTS.md。这样规则不打架、不重复、维护成本低，Agent 也不用纠结该听谁的。目录级规则文件等真有需要再说。

⸻

## 为什么记忆单独放 .ai/？

规则和知识是两回事。AGENTS.md 回答"AI 该怎么干活？"，.ai/ 回答"这个项目有什么值得长期记住的？"。分开放，AGENTS.md 才不会越长越肥。

⸻

## 与具体框架无关

这不是"Next.js Agent Rules"，是通用的 AI 编码代理规则。框架相关的东西放在项目记忆里：

PROJECT.md
Framework: Next.js
Version: ...

或者

PROJECT.md
Framework: Axum
Version: ...

核心行为不用变。

⸻

## 定制规则

AGENTS.md 是模板，不是合同。

* 留对你有用的章节，删掉没用的。
* 可以加团队专属规则（命名、提交规范、评审要求）作为新章节。
* AGENTS.md 一旦能用就别乱动；变化中的事实放进 .ai/，别塞进 AGENTS.md。
* 删了章节，记得把目录里的对应条目也删掉。

⸻

## 常见问题

**问：哪些 Agent 支持这套规则？**

答：任何支持 AGENTS.md 或类似项目级指令文件的 Coding Agent 都可以使用。Claude Code、Cursor、Codex、Cline、Roo Code、Windsurf 是目前的一些例子——请当作举例，不要当成兼容性承诺。

**问：选哪个语言目录？**

答：选团队读得懂的——`en/` 英文版或 `zh-CN/` 简体中文版。两个目录结构完全一样，只有语言不同。装一个就行，不用两个都装。

**问：.ai/ 和 Agent 自己的记忆一样吗？**

答：不一样。.ai/ 是经过筛选的项目专属知识，跨工具、跨会话长期有效；Agent 内部记忆是每个工具自己的，不共享。

**问：之后能加目录级 AGENTS.md 吗？**

答：能，但只在有明确、文档化的需求时。默认保持根目录一个 AGENTS.md。

**问：AGENTS.md 和工具自带规则冲突怎么办？**

答：保持两者一致。AGENTS.md 管项目行为，工具设置管工具行为。

⸻

## 最终原则

整套系统最重要的原则就几条：

先理解
不要猜
先调查
检查版本
理解状态
最小修改
实际验证
只记重要知识

要的不是一个"记得很多"的 AI，而是一个越来越懂这个项目、但不会被垃圾记忆污染的 AI Coding Agent。
